# VulnFlow test results — 2026-11-23

## Result

The existing 102-test suite passed before changes. After adding 17 rescan regression cases and fixing the issues below, **119 tests passed, with no failures or skips**, in 33.12 seconds. Backend/frontend lint, backend/frontend type checks, clean Alembic migration through `0007`, and the frontend production build passed.

The test run used synthetic data only. Tests ran against a dedicated PostgreSQL 16.14 cluster on port 55439, separate test and browser databases, Redis on port 56379, API on port 58000, and a production frontend build served through a local test proxy on port 55173. The application's existing processes on ports 8000/5173 were left untouched. Browser testing used the in-app browser; live imports and report generation used an actual Celery worker, not eager tasks.

## Rescan scenario

Baseline: Core `10.10.0.0/24` and DMZ `10.20.0.0/24`, three hosts, four findings. The next scan covered only `10.10.0.10`: SMB persisted, RDP disappeared, and TLS was new on that host. The other Core host and the DMZ host were omitted.

| Step | Verified result |
|---|---|
| Baseline import | Three hosts and four findings |
| Partial Core rescan | One new, one fixed, one persisting on the common host |
| Omitted hosts/ranges | Existing findings and last-seen dates preserved |
| RDP returns in third scan | Same finding ID; status reopened; reopen count 1; history preserved |
| Fourth scan loses credentials | Zero fixed; three not verified; current statuses remain open/reopened |
| Disabled plugin family | Missing finding remains open and appears under not verified |
| Older/equal host timestamps | Cannot prove a fix; comparison reports not verified |
| Missing/reversed start or completion dates | Import succeeds; findings stay open; no auto-fix |
| Late malformed XML after 550 hosts | Import fails and all prior batches roll back |
| Reparse | No duplicate occurrences or timeline entries |
| Scan deletion | Remaining clean evidence retained; prior fix date restored after deleting reopening; reopen count adjusted; later manual decisions preserved |

A finding remains unique by asset IP, plugin, port and protocol. “Fixed” means absence passed the modeled scan-coverage checks; it does not independently verify installation of a patch.

## Issues reproduced and fixed

| Issue | Before | After |
|---|---|---|
| Scoped import could modify another team's findings | A restricted analyst could submit a mixed-range scan and auto-close an out-of-scope finding | Every parsed host must belong to an assigned range before the file is queued; a mixed-range file is rejected as a whole |
| Incomplete host metadata could falsely close findings | Missing completion time or scan timestamps still allowed auto-fix, including through import-time fallback | Auto-fix requires scanner start and completion timestamps with end >= start; missing start is retained as unknown coverage |
| Comparison ignored lifecycle safeguards | Lost credentials or disabled families appeared as fixed while findings remained open | Separate not-verified count and list; date and completion checks also apply |
| Deleting the first clean scan reopened a still-fixed finding | Later clean evidence was ignored | Remaining qualifying coverage is used |
| Deleting a reopening lost fix metadata | Status became fixed with no fix date; reopen count stayed inflated | Prior fix date restored and deleted reopening removed from count |
| Scan deletion could override a later manual status | Matching status strings allowed an older scan event to win | Later status decisions are respected; unaffected manual findings are excluded from recalculation |
| Scoped dashboard exposed global scan totals | Core-only analyst saw seven scans, including unrelated ranges | Counts and last-scan metadata use visible hosts; verified four visible scans |
| Upload dialog retained old results | Done/progress links left the next opening stuck on previous results | Closing through these actions resets the dialog; repeated uploads work without refresh |
| Assignment comments were invisible | Comment text was stored after the assignment label but discarded by rendering | Full assignment note is displayed as escaped text |
| Sign-out retained the old screen | Server revoked the session, but clearing the query cache detached the active identity observer | Pending queries cancel; identity becomes null; other cached queries are removed; sign-in screen appears |
| Mobile import button lacked a name | Hidden button text left an unnamed control | Explicit accessible name added |

No database migration is needed for these changes. Existing historical findings are not bulk-reclassified. Reparse older scans when their coverage metadata needs to be reconstructed from the original files; missing original evidence cannot be recovered from import dates.

## Additional execution evidence

- **Large import:** 116,768,625 bytes (111.36 MiB), 120 hosts, 9,600 findings; real worker completed in 4.342 seconds. This is one local measurement, not a production capacity guarantee.
- **Concurrency:** two uploads covering the same host were queued together with different scanner dates. The newer clean scan determined the final fixed state regardless of processing order.
- **Worker unavailable:** uploaded a scan while the worker was stopped, verified queued status, restarted the worker, and verified completion with one finding. This verifies backlog recovery, not hard-crash recovery during an active transaction.
- **Reports:** CSV, XLSX, HTML and PDF generated and downloaded through the real worker. Core CSV contained exactly four rows, preserved reopened status, and excluded DMZ/load hosts. XLSX contents also excluded those hosts. Browser generation and download of a Core CSV succeeded.
- **Roles through the live API:** unscoped viewer and analyst, Core-only analyst, and restricted viewer with no assigned networks. Admin endpoints and scan deletion returned 403; hidden assets/scans returned 404; empty scope returned zero findings/assets/scans; mixed-range scoped upload was rejected.
- **Browser:** admin upload/rescan/compare/history/assignment workflow; escaped HTML-like assignment comment; viewer read-only details and denied admin route; scoped analyst showing only four Core findings; sign-out/account switching; network address map; assets, software, vulnerabilities, metrics, approvals, my work, users, audit, settings and reports rendered their expected headings.
- **Responsive checks:** dashboard and comparison at an effective 375 CSS-pixel viewport showed no document horizontal overflow; mobile navigation opened/closed. A narrower exploratory viewport around 312 CSS pixels showed crowded dashboard header content and slight overflow; that extra-small layout remains a UI limitation.
- **Existing regression coverage:** authentication/CSRF/session rotation, workflow/SLA/risk approvals/suppression, network scoping, parser safety, software inventory, report designer and backup/restore all passed in the full suite.

## Remaining limits

1. **Coverage confidence is still incomplete.** Individual plugin selection, changed port ranges, scanner errors, and other policy changes are not modeled. A valid host start/end pair plus credential/family checks cannot establish that every relevant check ran. For high-assurance remediation, keep scan policies comparable and review scanner warnings. A future per-host/per-check coverage model should explain why each disappearance is or is not verified.
2. **Asset identity is IP-based.** IP reuse can merge different machines; an address change creates a different asset. Hardware/cloud identifiers and asset reconciliation were not added.
3. **Queued recovery is verified; abrupt crashes are not.** Killing an active worker, Redis/PostgreSQL outages, disk exhaustion, and broker redelivery timing need separate fault-injection tests.
4. **Deployment checks remain.** Docker was installed but its daemon was unavailable, so container builds, nginx behavior, TLS cookies/headers, image scanning and the offline bundle were not executed. PostgreSQL 17 and other browsers were not exercised locally.
5. **Scoped uploads parse twice.** Validation runs in a thread pool before queueing, then the worker parses for ingestion. The 111 MiB benchmark used an unscoped admin; restricted-upload latency was not benchmarked.
6. Two dependency/configuration deprecation warnings remain (Starlette TestClient/httpx and Alembic path separator), plus Vite's existing future config-loader warning. They did not fail checks.

pnpm build
